# File observation

Use `packages/server/src/server/file-observer` for recursive filesystem observation. Create one observer service at the owning service boundary, subscribe roots through it, and close it during owner shutdown. Keep platform watchers, directory discovery, exclusion reconciliation, event batching, failure cleanup, diagnostics, and teardown inside the module. A consumer supplies a root and excluded subtrees; it must not branch on the platform or manage child watchers.

Do not replace the Linux implementation with `fs.watch({ recursive: true })`. Node 22 implements Linux recursion in JavaScript by walking the tree and watching every file and directory. Paseo's directory-only Linux watcher already exhausted resources before ignored-tree pruning and a watcher cap were added in [#794](https://github.com/getpaseo/paseo/pull/794).

Closing an observation must remain safe after its root is renamed or removed. Workspace archive removes owned worktrees while releasing observation references, so teardown cannot assume the watched path still exists.

`unsubscribe()` is an awaited barrier. Once it resolves, no scan, reconciliation, queued event, native handle, or callback may remain. `updateIgnore()` is the equivalent barrier for excluded paths: events queued below a newly excluded root cannot be delivered after it resolves. Treat path disappearance while scanning, attaching, or receiving a watcher error as rename/archive churn. Surface permission and resource errors so WorkspaceGit can enter bounded polling.

Linux topology repair is trailing-debounced and scoped to the renamed path. A file rename needs one classification stat; a new or moved directory scans only its subtree. Full-tree scans are reserved for startup and ignore-set replacement. The initial Linux scan conservatively emits existing files discovered before their directory watcher was installed; WorkspaceGit batches these into one refresh. Benchmark this startup cost with pre-populated trees.

Windows retains native recursive coverage for subtrees without exclusions. Along excluded paths, nonrecursive parent watches and recursive sibling watches physically omit the excluded tree. This topology is capped at 5,000 handles per observation.

macOS uses the pinned `@parcel/watcher` FSEvents backend with one recursive subscription per root and native exclusion filtering. All native watch registration, rescheduling and close operations run in a dedicated child process, including the nonrecursive project-root and file-explorer watches. This process boundary protects the daemon event loop from native mutex waits and libuv shared-stream rebuilds; using a promise around a synchronous native close does not provide that protection. Registration and unsubscribe acknowledgements remain awaited barriers. Closing suppresses late IPC events immediately; a 30-second native-operation deadline terminates only the watcher child, reports failure to all its consumers, and lets WorkspaceGit recover through bounded polling. Event IPC is coalesced with bounded queues and batches; overflow requests an inventory reconciliation. Include Parcel's optional platform binary and the watcher-host entry point when packaging the daemon. Keep Linux and Windows on their existing backends.

Both native backends share an ignored-pruned, directory-indexed inventory. Parent scans, inventory diffs/commits and subtree deletion share a four-millisecond or 256-entry work budget across observations. Each yield checks the observation generation; close and ignore replacement cancel obsolete work before it can deliver or mutate more entries. Classifications completing during a commit queue a follow-up scoped audit instead of modifying its directory buckets. Subscriber callbacks receive at most 256 coalesced paths per batch, with an event-loop turn between batches; pending paths retain their create/delete/update coalescing until delivery. These bounds cover JavaScript work, not filesystem wait, host scheduling pauses or arbitrary subscriber cost. Native events deliver promptly through those bounded batches. Named events trigger serialized shallow scans of their parent directories; known directory events also reconcile that subtree. This recovers concrete create and delete paths omitted by coalescing without walking the whole root for each edit. Classification is admission-controlled to 32 concurrent `fs.stat` calls, since `fs.stat` runs on the libuv threadpool the whole daemon shares. Startup and exclusion changes use an awaited full inventory barrier. FSEvents overflow notifications trigger a full inventory reconciliation; permission and resource errors still fail the observation into polling. A replacement exclusion stream registers before the old stream closes, preserving coverage during ignore changes. Activity arms a full safety audit 30 seconds after it settles, with a 30-second minimum interval and a five-minute starvation bound; pathless native events also trigger an immediate shallow root scan. Observation fails into polling rather than retaining more than 250,000 file and directory entries per root or one million entries across native observers in the daemon. The aggregate budget includes files classified between audits and is released on subtree deletion, exclusion replacement and close. Exhausted new observations fail before scanning; already admitted roots can replace their existing inventories at capacity. All startup, scoped and full audits share two cancellable admission slots across observer services. Each audit can hold a candidate tree and a shallow directory snapshot, each bounded by the 250,000-entry per-root limit; the conservative total envelope is therefore one million retained plus one million transient path entries, independent of fleet size. This bounds logical inventory entries rather than V8 heap bytes. The retained budget admits four maximum-size inventories while keeping aggregate memory independent of the number of individually valid repositories; excess roots use the existing bounded polling recovery. A repository that large is also expensive to poll, so degraded polling doubles its gap from 5 seconds to a 60-second ceiling while the workspace snapshot comes back unchanged, and resets to 5 seconds on the first change. Explicit reads still force a refresh; the ceiling only bounds how long an edit made outside Paseo stays undiscovered.

Sidebar membership retains Git metadata observation without recursively inventorying every checkout. Working-tree coverage follows executing agents and the visible client's focused agent or terminal; after the last execution or focus ends, retain coverage for one hour before releasing its inventory. Agent execution owns its subscription independently of connected clients. Explicit diff and file-explorer subscriptions retain their own coverage. Dormant sidebar dirty counts are cached; selecting the checkout refreshes them, and direct checkout reads reconcile edits made while coverage was suspended. Do not treat a host-wide checkout-status event subscription as a request to inventory every workspace: a large sidebar otherwise exhausts the shared native budget and forces the whole host into polling.

Read aggregate health from the owning observer service. Pending startup observations already own resources, so they count in diagnostics and are included in close and cancellation barriers. On macOS, native-event counters count notifications reaching JavaScript after native exclusion filtering and coalescing; they are not kernel event totals and cannot be compared directly with old raw `fs.watch` callback counts. Verify full registered coverage and tracked edit round trips before interpreting a lower event rate. Runtime metrics include active observations, native handles, tracked native files, pending events and immediate reconciliation work, scoped and full reconciliation activity and latency, and failure counts. `nativeTrackedFileCount` and other per-file counters are native-backend diagnostics only — the Linux backend keeps no per-file inventory and reports zero — so a cross-platform assertion belongs on delivered events, not those counters. Delayed safety audits do not count as pending work. Closing the service releases every subscription and clears its diagnostics. Do not add path lists, watcher handles, or platform-specific controls to this interface.

Git owns Git-ignore evaluation. The observer accepts absolute excluded roots and applies updates without replacing the observation or exposing its watcher topology. This keeps tracked files inside otherwise ignored directories observable and keeps Git policy out of the filesystem module. Observer events and exclusions use the subscription root's lexical namespace. Consumers must filter those paths without resolving each event/exclusion pair on disk: an ignored dependency install can otherwise block the daemon's event loop for minutes.

Workspace Git verifies each repository metadata subscription with a one-shot canary inside the Git directory. If the event does not round-trip through the subscription callback, treat the watcher as unavailable and enter degraded polling. Initial subscription failures and runtime errors both retry with bounded backoff. Initial setup has a ten-second deadline; background recovery allows up to two minutes for a healthy inventory under load. A subscription deadline aborts its inventory and closes native coverage immediately; wait for cancellation to settle before scheduling recovery so inventories never overlap for the same target. Closing the owning workspace or service makes pending recovery obsolete: its later timeout or rejection must settle normally, and a late subscription must still be released. Refresh working-tree Git-ignore exclusions from ignore-file events, newly observed directories, and watcher recovery, never from a healthy-watcher timer. `git ls-files` reports an ignored directory only once it exists, so new directory topology is a trigger in its own right; the refresh is edge-triggered per directory and debounced so a dependency install collapses into a couple of Git runs.

Cold initial snapshots run one workspace at a time and release their admission after the first Git snapshot, even when a busy checkout has queued successors. Publish that snapshot before remote authentication and PR-status enrichment. Forge work has a separate two-slot limit and owns neither shared Git-refresh nor background admission while it waits; a stalled remote must not strand the cold pass. Arm initial PR polling after that enrichment so cold targets do not fan out host/slug Git discovery. Explicit full refreshes still wait for the requested forge result, while subsequent cached checkout reads can use the published Git snapshot. Every cold background trigger, including metadata events and degraded polling, uses that same admission path. Warm background work coalesces outside the shared pool and re-enters its two-slot limit for each generation; initial cold work bypasses that warm queue, so the combined background budget remains three slots and retains one for explicit reads; an uncached explicit read retains admission headroom and high priority in the unchanged Git process scheduler. Watcher setup has an independent two-slot discovery lane: it shares in-flight facts with snapshot reads, but registration never waits for a full snapshot to complete. Facts older than one second are reloaded for the initial snapshot. Explicit reads therefore do not wait for watcher setup or the cold sidebar queue. No claim here bounds a running Git command or host filesystem I/O.

Admitted native inventories read at most 16 directories concurrently, so the shared two-audit limit bounds startup and warm reconciliation filesystem fanout to 32 directory reads. Closing an observation or replacing its ignore generation cancels a queued admission without waiting for other roots. This bounds descriptor pressure without multiplying filesystem or event-loop callback latency by a monorepo's entire directory count. Every admitted batch settles before cancellation or a scan error returns. Ignored-subtree checks use an ancestor index whose lookup cost depends on path depth rather than the number of excluded directories. Completed native registration and directory batches report inventory progress. During initial setup, this renews the ten-second idle deadline while retaining a two-minute absolute cap; a non-progressing subscription still degrades after ten seconds. Recovery remains capped at two minutes.

Git ignored-directory inventories (`ls-files -o -i --directory --exclude-standard`, including NUL-delimited directory suggestions) use a separate single-process background lane, limited to two starts per second and lower OS priority on Unix. They never occupy snapshot/read Git slots. Initial watcher seeds have priority over warm re-inventories within the background lane. Runtime Git metrics expose this lane under `inventory`, with `git-ignore-inventory` provenance and consumer suffixes. Working-tree topology and ignore-rule changes coalesce with a 30-second minimum gap after the previous inventory completes, including failures; an event during a pending inventory retains one trailing refresh. Ordinary updates to existing files still refresh Git status but do not inventory directory topology. Directory suggestions share pending inventories for their entire queue wait and start cache expiry at completion.

The real-filesystem contracts and daemon auto-archive lifecycle run in the normal server test suite. Use the scripts only for manual performance and soak work: `npm run measure:file-observer --workspace=@getpaseo/server` measures burst and sustained-create behavior, and `npm run repro:file-observer-teardown --workspace=@getpaseo/server` runs the teardown soak.

For macOS fleet-scale changes, run `npm run measure:workspace-watch-load --workspace=@getpaseo/server` through the host's heavy-job limiter. Set `PASEO_WATCH_LOAD_NEXT_ROOT` to an installed Next app's `node_modules`. The harness owns an isolated loopback daemon on an ephemeral port, scratch registry/home, real Git repositories and real FSEvents; it never connects to port 6767. The default fixture has 85 repositories, each with 160 packages and ignored dependency/build trees. `PASEO_WATCH_LOAD_FD_LIMIT` sets only the child process's descriptor limit (default 256); repeat at 1,024. The former live worker's exact limit was not recorded, so these are an explicit pressure envelope. `PASEO_WATCH_LOAD_OBSERVER_ENTRY` can select a preserved compiled observer for the native-only negative reproduction. A parent deadline bounds native teardown wedges.

Before activation, compare the candidate with the rollback baseline under the same load and observation duration, including cold startup, edit/build load, ignore replacement, cancellation and teardown. Require no increase in the count of distinct stalls over 10 seconds (also report the rate per hour), their maximum duration, or event-loop p99. Record exact window boundaries, workspace/file counts, descriptor limits, build schedule and competing host load. Use the same sampling method and resolution for both builds; compute p99 from each complete window's histogram, never by averaging interval percentiles. Missing baseline p99 or unmatched windows leave relative acceptance pending. Keep baseline reports and candidate measurements on the governing issue; historical stalls do not establish their cause.

All 85 workspace subscriptions must finish registration and deliver tracked edits; actual uncached `checkout_status` requests must complete under 10 seconds while the cold queue is still pending. Run the real Next build only after the full coverage barrier. The short harness run verifies these functional bars and reports loop stalls and a 10 ms histogram p99; it does not establish acceptance against an hour-scale baseline. Extend matched staging runs to the baseline's full window before activation. Record the fixture, measurements and build hashes on the governing issue. Passing staging does not authorize installation or a restart.

Checkout membership and workspace reconciliation read Git identity facts rather than dirty-worktree status. These reads coalesce per checkout while pending and use a separate two-job admission limit with `workspace-checkout-metadata` provenance, preventing a bulk registry pass from flooding the Git process queue.
